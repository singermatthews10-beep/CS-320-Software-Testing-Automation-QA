# CS 320 Software Testing, Automation, and Quality Assurance

This repository contains artifacts from my CS 320 Software Testing, Automation, and Quality Assurance course. The included files demonstrate my experience developing Java services, creating JUnit tests, validating software requirements, and applying testing strategies to improve software quality.

## How can I ensure that my code, program, or software is functional and secure?

I can ensure that my software is functional by first understanding the requirements and then creating tests that verify each requirement. During this course, I used JUnit testing to check both valid and invalid inputs for the contact service. Testing different situations helped me identify problems before they could affect the final application. I also learned that good testing should include positive tests, negative tests, boundary conditions, and exception handling.

Security also begins with careful validation and good programming practices. Programs should reject invalid data, protect sensitive information, and only allow expected inputs and operations. Regular testing, code reviews, and following secure coding practices can help reduce vulnerabilities while making the software more reliable.

## How do I interpret user needs and incorporate them into a program?

I begin by translating user needs into clear and measurable software requirements. Instead of only thinking about what the program should do, I consider the rules and limitations that the user expects the program to follow. For example, the contact service had specific requirements for contact IDs, names, phone numbers, and addresses. I used those requirements when developing both the program and the unit tests.

This approach helps ensure that the finished software solves the correct problem. Testing directly against the requirements also provides evidence that the program behaves the way the user expects.

## How do I approach designing software?

I approach software design by breaking a larger problem into smaller components with specific responsibilities. I first review the requirements, determine what classes and methods are needed, and then consider how those components will interact. After implementing each component, I test it before moving on to more complex functionality.

This course strengthened my understanding that testing should be part of the development process rather than something completed only after a program is finished. Designing software with testing in mind makes the code easier to maintain, improves reliability, and allows problems to be identified earlier in development.
